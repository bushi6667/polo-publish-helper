# Page3 面板默认行为调整

## 背景

1688 国际站发品页（page3 / publish 页）的 Polo 发品助手浮窗面板，当前默认展开在右上角。在批量发品场景下，面板默认展开会遮挡表单内容，且批量模式下用户主要是看日志和确认状态，不需要面板一直展开。

## 设计原因

1. **减少页面遮挡**：批量发品时页面自动跳转，面板默认展开遮挡右侧表单输入区，用户每次都需手动折叠
2. **批量模式优先**：批量发品是主要使用场景，面板主要用于查看当前产品信息和填入日志，不需要完整展开
3. **左侧停靠更合理**：1688 发品页核心操作区在中右部，面板放左边不遮挡主操作流

## 设计优点

1. **打开即用不挡事**：默认折叠 + 左边贴边，页面加载后不遮挡表单内容
2. **信息不缺失**：折叠态仍保留产品信息（行号、标题、类目、主图）和模式切换，用户可快速确认当前产品
3. **交互成本低**：点击 `+/−` 或 header 即可展开/折叠，原有拖拽功能完全保留
4. **视觉稳定**：left 定位下展开折叠时左边固定、右边伸缩，不跳动

## 能力边界

### 能做什么

- 页面初始加载后，面板处于折叠状态（宽 260px）
- 页面初始加载后，面板停靠在左上角（top: 60px, left: 0）
- 用户可随时点击 `+/−` 或 header 展开/折叠
- 用户可随时拖拽面板到任意位置
- 折叠态下日志仍正常写入，展开后可见
- 折叠态下模式切换（覆盖/追加）仍可用

### 不能做什么

- 折叠状态不跨页面/跨刷新持久化（刷新后回到默认折叠态）
- 拖拽位置不跨页面/跨刷新持久化（刷新后回到默认位置）
- 不影响 page2 面板的默认行为（page2 保持原样）
- 不改变任何填入功能的逻辑，只改变面板初始视觉状态

## 改动范围

仅修改 `chrome_extension/content/page3.js` 中 `createPage3Panel()` 函数：

1. `isCollapsed` 初始值：`false` → `true`
2. 面板初始位置：`right: 20px` → `left: 0`
3. 面板创建后主动调用一次 `togglePanel()` 应用折叠样式
