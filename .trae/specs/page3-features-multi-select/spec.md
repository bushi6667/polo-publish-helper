# Page3 产品特性多选改造

## 背景

1688 国际站发品页（page3 / publish 页）的产品特性字段，在不同类目下处理方式不一致：
- Shirt / T-shirt / 默认类目：使用默认 search 模式（单选下拉）
- Polo：使用 `forceMode: 'direct'`（直接输入文本）
- Hoodie / Sweatshirt：使用 `forceMode: 'tag'`（标签多选）

实际业务中，产品特性通常有多个值（如 `Breathable, Quick Dry, Anti-Shrink`），当前单选模式只能填入一个特性，导致信息缺失。

## 设计原因

1. **业务需求匹配**：产品特性天然是多值属性，一个产品通常具备多个特性，单选模式不符合实际业务场景
2. **类目体验一致**：不同类目相同字段的交互模式不一致，增加维护成本和用户认知负担
3. **已验证方案**：Hoodie/Sweatshirt 类目已使用 tag 模式实现多选，经过实际使用验证可行
4. **最小改动原则**：复用已有的 tag 模式实现逻辑，只需修改字段配置，不需要新增核心逻辑

## 设计优点

1. **多值完整填入**：支持逗号分隔的多个特性值逐个输入选择，确保产品信息完整
2. **类目一致性**：所有类目产品特性统一使用 tag 模式，行为一致，降低维护成本
3. **智能匹配**：输入后自动搜索匹配选项，找到则点击选择，找不到则回车确认自定义值
4. **兼容现有数据**：输入值按逗号（中英文）自动拆分，单个值时行为与单选一致
5. **复用成熟逻辑**：直接复用 Hoodie/Sweatshirt 已验证的 tag 模式实现，风险低

## 能力边界

### 能做什么

- 所有类目（Shirt / T-shirt / Polo / Hoodie / Sweatshirt / 默认）的产品特性字段统一为 tag 多选模式
- 支持逗号（`,`）和中文逗号（`，`）分隔的多个特性值
- 逐个输入每个特性值，自动搜索下拉选项并点击匹配项
- 找不到匹配选项时，按回车确认自定义输入值
- 自动清除已有标签后再填入新值（避免重复）
- 单个特性值时正常工作，兼容单值场景

### 不能做什么

- 不修改 tag 模式的核心填入逻辑（复用现有实现）
- 不改变其他字段的填入模式
- 不处理特性值的排序、去重（按输入顺序填入）
- 不支持选项的模糊匹配高级策略（使用现有 normalizeCompare 逻辑）
- 不保证页面不支持多选时也能强制多选（依赖页面组件本身支持 tag 模式）

## 改动范围

仅修改 `chrome_extension/content/page3.js` 中 `buildAttributeFields()` 函数：

1. **Shirt 类目**（line 141）：产品特性字段添加 `forceMode: 'tag'`
2. **T-shirt 类目**（line 170）：产品特性字段添加 `forceMode: 'tag'`
3. **Polo 类目**（line 194）：产品特性字段 `forceMode: 'direct'` → `forceMode: 'tag'`
4. **默认类目**（line 235）：产品特性字段添加 `forceMode: 'tag'`

Hoodie / Sweatshirt 类目（line 226）已为 `forceMode: 'tag'`，无需修改。
