# PS编辑脚本注入可靠性修复 — 设计文档

## 背景

`background.js` 中的 `startPsEdit` 负责打开 Photopea 编辑页面并向其注入拦截脚本。当前实现使用固定 `setTimeout(..., 3000)` 等待 3 秒后注入，导致以下问题：

1. 网络慢或 Photopea 加载慢时，3 秒后页面仍在 `loading` 状态，`chrome.scripting.executeScript` 抛出 `Cannot access contents of the page`。
2. 用户在此期间关闭标签页，抛出 `No tab with id`。
3. 网络快时，固定等待造成不必要延迟。

## 设计原因

为何从"固定延迟"改为"事件驱动等待"？

- Chrome 扩展 API 提供了 `chrome.tabs.onUpdated` 事件，可精确监听标签页状态变为 `complete`。这是浏览器原生信号，比人为估算的固定延迟更可靠。
- `chrome.scripting.executeScript` 要求目标页面处于可访问状态。只有 `status === 'complete'` 时，才能确保页面框架已初始化、URL 已稳定、权限检查可通过。
- 固定延迟属于"猜测式编程"，无法适应不同网络环境；事件驱动属于"响应式编程"，随实际情况自适应。

## 设计优点

1. **可靠性提升**：无论网络快慢，只在页面真正就绪后注入，消除权限/访问错误。
2. **性能优化**：页面加载快时无需多余等待，立刻注入。
3. **可维护性**：意图明确（等页面加载完成），代码自解释。
4. **健壮性**：增加超时机制（如 30 秒），防止 Photopea 长期无响应时无限挂起。
5. **用户体验**：注入前检查标签页是否存在，若被关闭则给出明确错误信息，而非抛出底层 Chrome API 异常。

## 能力边界

### 能做什么
- 处理 Photopea 正常网络加载、慢加载场景下的脚本注入。
- 在标签页被提前关闭时给出可控的友好错误。
- 在超时时给出明确提示，避免任务无限挂起。

### 不能做什么
- 无法解决 Photopea 网站本身不可用（404/500/域名变更）的问题。
- 无法在用户主动撤销扩展 host 权限后成功注入（此时应引导用户检查权限）。
- 无法加速 Photopea 本身的加载速度，只能等待其就绪。
